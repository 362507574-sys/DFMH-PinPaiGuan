# 品AI品牌官｜帝王使用指南

## AI品牌官是什么

AI品牌官只是总控调用的业务组织分支，不是总控主线或另一个控制中心。这个组织分支只拥有品牌定位、品牌视觉、品牌传播三个核心 Skill；总控负责识别任务和决定是否调用它。

## 你需要做什么

帝王只需用大白话说明品牌目标和这次新增的变化，例如“客户记不住我们”“价值说不清”“视觉不像同一个品牌”“这次新品面向餐饮老板”。无需提供代码、文件位置、工具名称或技术参数。

如果任务已有企业资料、品牌定位、视觉规范和已确认成果，执政官会自动读取精确版本并沿用，不要求帝王再次输入。只有缺少会改变最终业务结果的关键信息、不可替代素材，或涉及付费、对外发布、不可逆覆盖、账号权限时，才会一次性询问最少必要内容。

## 执政官会怎么做

1. 识别企业、品牌和任务归属；
2. 先查飞书知识库，再吸收对话中的企业内部信息，最后检索互联网公开资料；
3. 把事实、外部证据、专业判断、假设和未知分开；
4. 根据目标只启用本次真正必要的定位、视觉或传播内部模块；下游 Skill 自动读取已确认的上游结果；
5. 需要其他组织能力时形成合同化协作请求，不要求帝王重复输入已有资料；
6. 先做规则审核，再由独立品牌专业角色复核；不合格时只改受影响部分，同一根因最多三轮；
7. 同时生成帝王易读的摘要和总控可继续使用的结构化交接包，再交给帝王看候选与关键业务选择；
8. 把帝王反馈与验收结果保存为候选反馈和试运行证据，不把它直接转成正式品牌资产。

飞书知识返回 `no_hit` 或 `degraded` 时，执政官会说明本次知识覆盖限制并继续安全可做的部分，不会假装查到资料。

根注册表当前为 `status = designing`、`acceptsFormalTasks = false`，品牌定位、品牌视觉、品牌传播也都处于根权威 `designing`。组织配置里的三个 `pilot` 只是组织侧候选验证成熟度，不等于根权威成熟度。在根控制中心未来明确升级为 `operational` 且 `acceptsFormalTasks = true` 前，AI品牌官只能形成候选与验证证据，不得正式接单、不得正式晋级、不得将任何结果写入 `outputs/` 作为正式成果。

## 你会看到什么

交付会用“结论 + 依据 + 下一步建议（可选）”说明：

- 品牌应该占据什么心智位置；
- 面向谁、解决什么问题、凭什么相信；
- 哪些是企业事实，哪些来自公开资料，哪些仍是假设；
- 候选经过帝王反馈后发生了哪些变化，以及还缺哪些验证证据；
- 有哪些限制或风险需要后续处理。

系统不会把全部内部模块都展示成需要帝王逐项批准的技术清单。帝王主要看到候选方向、推荐理由、淘汰原因、仍待确认的关键业务选择，以及结果与品牌目标是否一致。

## 海报不好看时怎么淘汰

普通宣传海报由公共海报 Skill 负责具体制作，AI品牌官负责品牌策略、审美对照和最终质量否决：

1. 先查硬否决：产品或品牌失真、核心文案错误、主体不可识别、参考审美方向明显跑偏等问题一旦出现，即使分数很高也直接淘汰；
2. 再按 100 分制检查品牌策略、视觉审美、信息效率、品牌一致性、制作完成度和渠道适配；
3. 同时做 3 秒识别、缩略图、灰度、同尺寸并排、隐藏文字、只看文字层级、参考视觉 DNA 与品牌/产品匹配七项对比；
4. `90–100` 分为优选，`80–89` 分可进入候选，`70–79` 分定向返工，低于 `70` 分淘汰；
5. 同一问题最多返工三轮，第三轮仍不过就停止，并把问题证据、已尝试修正和需要补充的业务信息返回总控，不拿低质量图凑交付。

## 当前能力边界

品牌定位、品牌视觉和品牌传播三个核心 Skill 均已建立并完成组织侧自动化候选验证，当前统一为 `pilot`。普通宣传海报的根登记成熟度当前为 `operational`，但不会因此让 AI品牌官取得正式接单资格；淘宝电商套图仍是根级 `pilot` 公共能力。控制中心和同级协作通道没有被本组织当作可直接调用的正式生产连接。

当前 `rootControllerRegistration = registered_designing`，含义是总控已经能够识别本组织和三个 Skill，但根权威仍是 `designing`、`acceptsFormalTasks = false`。因此它仍是试运行候选，不是“正式上线”，不会绕过候选、证据、验收和根级升级门槛。

## 验收时只需看四件事

1. 是否符合企业真实情况；
2. 是否让目标客户容易理解和记住；
3. 是否有清楚、可核验的依据；
4. 是否明确保持候选状态，没有把反馈误写成正式结果。

不满意时直接描述感受或目标效果，执政官会在原任务归属下连续修改、复查和再交付。
