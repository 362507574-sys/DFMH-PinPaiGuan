# 品牌传播试运行工作流

## 1. 适用范围与边界

本工作流只适用于 `brand-communication`：品牌信息体系、内容母题、真实品牌故事、企业介绍、创始人 IP、重大品牌传播战役及一致性审核候选。它输出品牌底层叙事和协作简报，不接管增长战略官的日常获客运营，也不接管成交官的销售脚本。

根权威状态保持 `designing`，`acceptsFormalTasks = false`。当前只形成候选与验证证据，不得正式接单、不得对外发布、不得写入 `outputs/`。

## 2. 输入门禁

开始前必须具备：

1. 唯一企业、项目、任务和主责归属；
2. 已确认品牌定位的精确 `artifactId@version` 与 SHA-256；
3. 适用时已确认视觉规范的精确 `artifactId@version` 与 SHA-256；
4. 产品、案例、品牌起源、企业与创始人经历的事实证据及可公开边界；
5. 按 `shared/FEISHU_KNOWLEDGE_PREFLIGHT_STANDARD.md` 保存的知识前置凭证；
6. 本次传播目标、范围、时间、重大变化以及增长官、成交官所需的合同化交接边界。

定位或视觉依赖冲突、故事和头衔无证据、要求保证增长或自动发布时，输入门禁不通过。

## 3. 执行步骤

1. 用 `scripts/brand_project_workspace.mjs` 恢复原任务，用 `scripts/brand_task_planner.mjs` 生成有界传播计划。
2. 校验定位和视觉依赖的企业、项目、版本与 SHA-256，不读取模糊 `current/latest`。
3. 将事实、公开来源、专业判断、推断、假设、未知和禁止公开信息分开。
4. 建立核心价值、传播主张、信息层级、信任理由、品牌语气、常用词与禁用词。
5. 建立品牌、产品、用户、信任四类长期内容母题及偏离边界。
6. 只用已核实事实形成品牌故事、企业介绍、产品故事和案例；无证据部分转为取证计划。
7. 形成创始人 IP 的真实角色、专业标签、人格价值观、语气和可说/不可说边界。
8. 重大传播项目形成一个传播主题、大创意、核心信息、视觉方向、关键资产和阶段节奏。
9. 分别输出给 AI增长战略官和 AI成交官的合同化简报，锁定事实、必保信息、可适配项、禁用表达和回传指标。
10. 用证据包、交付契约及规则/专业双重审核检查定位、视觉、故事、IP和协作输出一致性。
11. 候选留在当前项目组织工作区，跨组织共享只提交控制中心发布请求。

## 4. 输出与验收

输出至少包括：品牌信息体系、内容母题、表达边界、真实品牌故事、企业介绍、创始人 IP、重大传播战役、核心文案候选、增长官简报、成交官简报和一致性审核记录。

候选验收必须同时满足：

- 定位与视觉来源精确且可验证；
- 信息层级明确，一个项目只有一个传播主题；
- 故事、IP、案例与宣称均有事实依据；
- 品牌传播、日常增长运营和成交执行边界清楚；
- 协作简报固定版本、事实锁与回传指标；
- 规则审核和品牌专业审核各完成一次；
- 无虚假第一、保证结果、虚构稀缺、自动联系或发布。

## 5. 异常、重试与停止

- 临时知识、网络或文件故障最多重试两次，并保存真实失败原因；
- 信息层级、依赖或事实映射错误最多修正三轮；
- 同一根因连续三轮仍失败必须停止，保留检查点、交接记录和可恢复入口；
- 定位/视觉依赖错误、跨企业读取、故事无证据、协作结果错版本时停止定案；
- 要求虚构事实、付费、投流、联系客户、外部发布、账号权限或根成熟度变更时立即停止。

## 6. 真实验收边界

当前传播证据为独立模拟评测，尚未构成真实企业验收。下一门槛必须用真实企业的定位、视觉、事实资料与修改反馈完成一次传播任务，并证明增长官和成交官能按固定版本读取简报、反馈结果且不造成主责漂移。

内部真实任务通过后仍保持 `designing / acceptsFormalTasks = false`，不得正式接单。是否升级只由根控制中心基于完整证据另行决定。
