# 品AI品牌官｜组织侧详细说明

## 1. 系统位置

AI数字员工控制中心采用“一个控制中心、五个业务组织、十五个核心技能”结构。五个业务组织分别是 AI掌舵官、AI增长战略官、AI成交官、AI组织官和AI品牌官，每个组织固定三个核心技能。

AI品牌官只是总控按任务调用的业务组织分支，不是总控主线，也不负责控制中心、根路由或五个组织的总体调度。该组织分支只拥有品牌定位、品牌视觉、品牌传播三个核心 Skill。

品AI品牌官在本组织目录内建设品牌增长系统，三个核心技能为：

1. 品牌定位：明确服务对象、心智位置、价值主张、竞争差异与表达边界，组织配置当前为 `pilot`；
2. 品牌视觉：把定位转化为稳定的视觉识别与审核规则，组织配置当前为 `pilot`；
3. 品牌传播：把定位转化为一致的传播主题、内容框架与表达规则，组织配置当前为 `pilot`。

三个技能合计计入全系统十五个核心技能。普通宣传海报和淘宝电商套图属于根级公共能力，不占三个名额。

这里三个核心 Skill 的 `pilot` 都只表示组织侧候选验证成熟度，不等于根权威成熟度。`control-center/registries/organizations.json` 是权威来源：本组织当前 `status = designing`、`acceptsFormalTasks = false`，品牌定位、品牌视觉、品牌传播三个技能的根权威状态均为 `designing`。

## 2. 当前真实边界

- `rootControllerRegistration = registered_designing`
- `peerOrganizationCalls = contract_only`
- 飞书知识写回 = `disabled`
- 普通宣传海报 = `formal` 公共能力
- 淘宝电商套图 = `pilot` 公共能力

`registered_designing` 的依据是根运行登记已经绑定本组织配置和三个 Skill 路径；它只消除“本地未登记”的健康警告，不代表 `operational`。本组织未获得根路由、根调度、根注册表改写、同级组织内部资产或根保护基线的管理权。根权威仍为 `designing`、`acceptsFormalTasks = false`，根控制中心审查凭证也不使本组织具备正式接单资格。

在根控制中心明确把本组织升级为 `operational` 且 `acceptsFormalTasks = true` 前，AI品牌官只能形成候选与验证证据，不得正式接单、不得正式晋级、不得把候选写入 `outputs/` 作为正式品牌资产。帝王验收当前只形成候选反馈和试运行证据，不能绕过根权威门槛。

## 3. 主责与协作

1. 总控识别任务后决定是否调用 AI品牌官组织分支，并把具体品牌任务分派给该分支。
2. 一旦总控把具体品牌任务分派给 AI品牌官，后续补充、修订、恢复和重新连接沿用原归属；这里的“主责”仅指该品牌任务的执行责任，不表示品牌官成为总控主线。
3. AI增长战略官、AI成交官、AI组织官或AI掌舵官可以通过合同化候选提供输入，但不能静默替代品牌官的总审。
4. 普通宣传海报由根级正式公共能力负责生产，AI品牌官负责品牌一致性和最终审核；淘宝电商套图仍沿用根级试运行 Workflow，不得视为正式 Skill。

## 4. 企业隔离与资产分层

企业隔离覆盖企业、品牌、任务、素材、证据、候选、协作请求、审核记录和正式资产。任何跨企业复用都必须重新取得授权并保留来源，不得因为名称相近而自动合并。

候选与正式隔离：

- 企业品牌档案放入 `brands/enterprises/` 的对应企业空间；
- 品牌定位试运行放入 `temp/positioning-jobs/`；
- 未经审核的定位、视觉或传播结果一律为候选；
- 当前品牌官总审与帝王验收只补充候选反馈、版本和试运行证据，结果继续留在候选区；
- 只有未来根权威状态同时达到 `operational` 与 `acceptsFormalTasks = true`，并另行通过当时有效的正式 Workflow，才具备正式晋级的必要前提；
- 候选失败、知识降级、协作缺失或帝王验收都不能用来绕过根门槛。

## 5. 证据与可靠性

资料顺序固定为“飞书知识库 → 对话补充 → 互联网公开检索”。先取得可追溯知识，再补企业内部事实，最后用公开来源验证市场与竞争信息。每条结论标记来源类别，无法证实的内容保留为假设或未知。

飞书返回 `no_hit` 或 `degraded` 时，必须告知帝王本次知识覆盖的限制并继续完成可安全推进的部分；不得卡住任务，也不得虚构飞书知识库依据。

## 6. 根章程与范围保护

`ORGANIZATION.md` 由根控制中心所有。本文件承载组织侧详情，因此当前没有不可替代的章程导航需求，原章程保持字节完全不变。范围守卫发现根漂移时，本组织只能生成幂等 handoff 请求根控制中心审查；组织侧 rebaseline 永久拒绝。

## 7. 三个独立工作流与统一质量档案

- 品牌定位：`workflows/BRAND_POSITIONING_PILOT.md`
- 品牌视觉：`workflows/BRAND_VISUAL_PILOT.md`
- 品牌传播：`workflows/BRAND_COMMUNICATION_PILOT.md`
- 统一“快、准、稳”机器档案：`quality/organization-quality.json`

三个 Workflow 分别锁定适用范围、输入门禁、执行步骤、输出验收、异常重试、停止条件和真实验收边界。当前证据等级仍为模拟验证，真实企业验收未完成；因此组织仍保持 `designing`、`acceptsFormalTasks = false`。
