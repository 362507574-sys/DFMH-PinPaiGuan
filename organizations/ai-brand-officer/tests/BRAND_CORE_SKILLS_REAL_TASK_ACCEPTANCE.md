# AI品牌官三个核心 Skill V2｜真实任务验收记录

## 1. 使用边界

本文件是正式真实业务试运行的验收记录模板，不是模拟测试报告。当前自动化测试只证明规划、证据、版本、语义门禁、双审核、三轮返工、打包和项目隔离链路能够按契约运行。

**以下八类任务尚待使用真实企业资料、真实候选和帝王实际反馈逐项运行；在真实记录完整前，不得宣称三个 Skill 已完成正式业务验收、已正式接单或已连接总控。**

每次试运行必须：

1. 只在对应 `business-projects/<enterpriseId>/<businessProjectId>/organizations/ai-brand-officer/` 临时组织工作区执行；
2. 固定上游 `artifactId@version` 与 SHA-256，不使用 `current` 或“最新版”；
3. 保存真实飞书知识凭证；`no_hit` 或 `degraded` 必须如实记录但不得伪造命中；
4. 规则审核与专业审核使用不同审核身份；
5. 不直接写 `shared-artifacts/` 或 `outputs/`，候选只返回总控；
6. 帝王反馈只沉淀到当前企业、当前项目，跨项目复用必须有总控固定导入快照。

## 2. 统一记录字段

每例都必须完整填写以下字段，不适用项写“本例不适用”并说明原因：

- 输入版本：企业、项目、任务、上游成果的精确版本与 SHA-256；
- 所选模块：实际选择模块、跳过模块及理由；
- 证据凭证：飞书 receipt 路径、SHA-256、状态、对话补充和公开来源；
- 候选：候选 ID、内容或图像文件、候选 SHA-256；
- 双审核：规则审核者、专业审核者、硬否决、评分和审核 SHA-256；
- 返工轨迹：根因、每轮处理、输入变化、验证结果和停止条件；
- 最终状态：`candidate_ready`、`blocked` 或 `returned_to_control_center`；
- 帝王反馈：通过、否决、修改意见，以及仅限本项目的可执行偏好。

## 4. 完成判定

只有八类真实试运行均有完整字段、可核验文件和帝王实际反馈，并且没有未关闭的关键问题时，才可提交“真实业务验收完成”的候选结论。该结论仍由总控按根权威状态决定是否晋级；AI品牌官组织分支自身无权宣布正式接单、正式发布或根连接完成。
