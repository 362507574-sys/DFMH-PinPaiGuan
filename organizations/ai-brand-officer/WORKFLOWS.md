# 品AI品牌官｜统一工作流

## 1. 标准链路

所有品牌定位、品牌视觉与品牌传播试运行严格按以下顺序执行：

AI品牌官是总控调用的业务组织分支，只拥有品牌定位、品牌视觉、品牌传播三个核心 Skill，不承担总控主线或总体调度职责。

### 三个核心 Skill v2 统一执行闭环

> 总控分派并绑定企业、项目与任务
> → 飞书知识前置
> → 动态规划本次真正需要的内部模块
> → 绑定上游成果的精确 `artifactId@version + SHA-256` 与本次证据
> → 只执行所选模块
> → 规则审核
> → 独立专业审核
> → 对未通过项定向返工（同一根因最多三轮）
> → 生成面向帝王的人类版摘要与面向总控/授权下游的结构化交接包
> → 返回总控，由总控决定后续发布、版本切换或继续协作

五个共用运行组件分别负责动态规划、证据约束、质量门禁、调试恢复和双层候选打包，不是第四个核心 Skill。定位四模块、视觉五模块、传播四模块均是对应 Skill 的内部能力，系统不会为了“流程完整”而机械全开。

`blocked` 不是把低质量结果当成失败交付，而是停止继续消耗，把已完成内容、失败根因、尝试过的修正、剩余风险、所需业务输入和安全恢复位置一并带证据返回总控。AI品牌官只在当前项目的组织任务工作区形成候选，不直接写 `shared-artifacts/`，不自行发布或切换正式版本。

以下组织级试运行链路继续负责解释资料来源、协作候选和帝王反馈：

> 总控分派并调用 AI品牌官组织分支
> → 绑定企业与品牌
> → 根级飞书知识前置（先查飞书知识库）
> → 对话补充内部事实
> → 互联网公开检索
> → 证据分类
> → 品牌定位试运行，或调用品牌视觉/品牌传播 Skill（定位 → 视觉 → 传播按依赖自动读取）
> → 必要时形成协作请求候选
> → 回收并审核协作结果
> → 候选定位、视觉或传播成果
> → 品牌官总审
> → 帝王验收（当前只形成候选反馈与试运行证据）
> → 候选与验证证据归档
> → 未来仅在根权威升级为 `operational` 且 `acceptsFormalTasks = true` 后，进入当时有效的正式晋级流程

任何步骤缺少必要输入时，只暂停受影响的分支；不得跳过企业绑定、证据分类、品牌官总审或帝王验收。

根注册表当前为 `status = designing`、`acceptsFormalTasks = false`，三个核心技能均为 `designing`。组织配置中的三个核心 Skill 均为 `pilot`，只表示组织侧候选验证成熟度，不等于根权威成熟度。在上述根门槛升级前，本流程只能形成候选与验证证据，不得正式接单、不得正式晋级、不得写入 `outputs/` 正式成果。

本组织当前 `rootControllerRegistration = registered_designing`，只表示根运行登记能够定位本组织配置和 Skill 路径；不改变上述 `designing / acceptsFormalTasks = false` 门槛。三个 Skill 的独立执行细节分别以 `workflows/BRAND_POSITIONING_PILOT.md`、`BRAND_VISUAL_PILOT.md`、`BRAND_COMMUNICATION_PILOT.md` 为准。

## 2. 分步规则

### 2.1 入口与归属

总控负责识别任务、确定组织归属并调用 AI品牌官分支。分支接到品牌任务后只负责本任务范围内的品牌工作；续问、修改、恢复和重新连接沿用原任务归属，不取得总控路由、其他组织调度或系统主线权限。

### 2.2 企业与品牌绑定

先确认企业、品牌、用途、受众、任务编号和资产版本。企业隔离贯穿素材、证据、候选和正式结果；无法确认企业归属时，不读取其他企业资产。

系统只读取总控写入当前任务上下文的可读成果，并逐项校验企业、项目、`artifactId@version`、SHA-256 和来源组织。不能核验的“最新版”、跨项目直接引用或被改写的哈希均停止受影响分支。

### 2.3 知识与资料顺序

1. 根级飞书知识前置：按 `shared/FEISHU_KNOWLEDGE_PREFLIGHT_STANDARD.md` 只读检索并保存凭证；
2. 对话补充：补齐企业内部事实、目标、限制、品牌历史和帝王明确偏好；
3. 互联网公开检索：核验市场、竞品、行业表达和公开事实。

飞书状态为 `matched`、`no_hit` 或 `degraded` 都继续任务。`no_hit` 或 `degraded` 时必须告知覆盖限制，保存真实状态，不得卡住后续，也不得伪造来源。

### 2.4 证据分类

每条输入和结论分类为：飞书原文、企业内部事实、对话补充、互联网公开来源、专业判断、推断、假设或未知。没有读取正文的飞书候选不能作为已使用知识。

### 2.5 品牌定位试运行

品牌定位的组织配置当前为 `pilot`，只代表组织侧候选验证成熟度。试运行至少形成目标客户、心智位置、价值主张、差异化理由、支持证据、表达边界、风险和待确认项；成果只进入 `temp/positioning-jobs/`。

### 2.6 品牌视觉试运行

品牌视觉自动读取已确认的定位结果，把心智、用户、场景与差异化证据转成视觉策略、参考视觉 DNA、三个可比较方向、视觉系统规则和应用边界。Logo、VI、门店、包装、宣传海报与电商套图按各自生产能力分流；本 Skill 负责品牌一致性与审核，不冒充生产、施工、印刷或公共生图能力。

视觉候选在进入通用质量门禁前，先做语义复验：长期视觉工作必须具备可信定位依赖；方向必须恰好三个、各有唯一资产且三组两两差异可核验；审美档案只能属于当前企业与项目，跨项目复用必须由总控建立固定版本导入快照。首次项目可以真实没有审美档案，但必须明确为 `null`，不能用空对象伪装，也不能因此绕过三个方向门禁。

调用普通宣传海报公共 Skill 时，运行时现场核对公共登记成熟度、允许调用的组织、当前项目授权和总控任务绑定，缺一项即拒绝正式执行。公共海报 Skill 负责生产，AI品牌官拥有品牌策略与质量否决权：硬否决优先于分数，随后执行 100 分制、七项可视对比和最多三轮定向返工。

### 2.7 品牌传播试运行

品牌传播自动读取已确认的定位与视觉规范，形成品牌信息体系、内容母题、真实品牌故事、创始人 IP 定位、重大品牌传播战役与一致性审核规则。抖音、小红书、公众号、私域的日更运营、投放获客、销售话术、客户培育和复购设计属于 AI增长战略官或 AI成交官；品牌传播只输出可复用的品牌底层与协作简报。

传播规划不会允许显式选择的模块删掉目标已经明确要求的必要模块。所有传播任务都固定读取可信定位；内容传播和品牌战役还必须读取可信视觉成果，品牌故事或创始人 IP 若暂不依赖视觉，必须显式记录“不适用/待补”，不能伪装已绑定。确认性主张必须让候选正文、`claimDigest` 与每条绑定证据的真实主张三方一致；只对上 `claimKey` 不算证据成立。

传播策略规则、语义校验器和契约 Schema 共同形成任务内不可变策略上下文。恢复时发现规则缺失或漂移，任务转为 `policy_migration_required` 并保留迁移审计；旧的通过审核不得复用。

### 2.8 协作候选

需要战略、增长、成交或组织输入时，只形成协作请求候选。当前 `peerOrganizationCalls = contract_only`，不得直接读取同级组织内部任务或假设协作连接可用。回收结果后，AI品牌官检查企业、任务、证据、版本和结论边界；不合格结果退回候选，不改变主责。

### 2.9 审核与候选归档

候选成果先通过规则审核，再由独立的品牌专业审核角色复核；两个角色不得由同一身份兼任。只有双审核通过且调试状态允许的候选才能生成双层交接包。帝王验收当前用于形成候选反馈和试运行证据，不是正式晋级授权。根注册表未达到 `operational` 与 `acceptsFormalTasks = true` 前，任何验收结果仍为候选。

## 3. 公共能力分流

- 普通宣传海报的当前根权威成熟度 = `operational`：按根级海报 Skill 与 Workflow 生产，AI品牌官做品牌一致性总审。早期组织文档中的 `formal` 只是历史组织侧分类，不是当前根权威状态；运行时始终以 `public-skills/registry.json` 为准。
- 淘宝电商套图 = `pilot` 公共能力：按根级试运行 Workflow 执行，不能包装为正式 Skill 或正式交付通道。

两项公共能力不计入品牌定位、品牌视觉、品牌传播三个核心技能。

## 4. 候选与正式隔离

试验输入、协作请求、知识凭证、审查草稿、帝王反馈和候选成果留在组织 `temp/`。当前不得把任何定位候选、总审结果或帝王反馈写入组织 `outputs/` 作为正式品牌资产。未来即使根状态升级，也必须重新读取当时有效的正式 Workflow，不得沿用本试运行文档自动晋级。

## 5. 异常与停止

- 跨企业、越权读取、伪造证据、绕过验收、把试运行描述成正式能力时立即停止；
- 临时网络、限流或可修正字段问题可有限重试；
- 同一根因连续修复三轮仍失败时停止，保存日志与证据并 handoff；
- 恢复执行必须沿用稳定的操作标识和幂等键；发现任务租约冲突、恢复文件损坏或策略上下文漂移时停止受影响分支，不重复交付；
- 根保护范围变化时运行只读范围守卫，组织侧不得更新或重建基线。
