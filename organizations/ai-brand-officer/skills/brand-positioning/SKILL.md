# 品牌定位

## 帝王版成果输出

专业交付统一规则：一级标题必须使用固定编号并去掉“技能”后缀；二级标题使用“1.1”式固定编号；三级标题依次使用“核心判断、深度分析、依据与边界、落地建议”并使用“1.1.1”式固定编号；四级标题继续拆分为“关键变量、推导逻辑、已知事实、待验证信息、执行动作、验收指标、风险与停止条件”并使用“1.1.1.1”式固定编号。每个业务分析子项至少500个有效字符，必须形成该岗位专属的专业推导，事实、推断与信息缺口分开，必要说明使用括号标注；禁止统一模板扩写、重复套话或用篇幅冒充分析深度。

唯一目录事实源为 `control-center/registries/organization-output-standard.json`。本技能在帝王版组织 Word 中固定使用一级章节“品牌定位”，并严格按以下顺序输出：

1. 品类定位
2. 用户定位
3. 差异化定位
4. 心智占位

每个栏目必须基于产品能力、目标客户、实际替代与企业可兑现证据；不得用通用形容词冒充差异化。仍缺少企业内部不可替代事实时写明：`信息不足，暂时无法形成可靠分析。当前缺少：<具体信息>。` 品牌架构、命名风险、证据和验证方式融入对应栏目，不新增帝王版目录。

## 概述

用证据回答“品牌是什么、为谁服务、为何不同、凭什么相信、长期记住什么”。证据不足时形成待验证候选，不把推断包装成事实。

本 Skill 是总控调用的 AI品牌官分支能力，不是根路由或总控主线。每次执行都实时读取 `control-center/registries/organizations.json` 中 AI品牌官的 `status`、`acceptsFormalTasks` 与核心 Skill 状态，不把任何一次读取结果写死在 Skill。只有根权威显示组织为 `operational` 且 `acceptsFormalTasks` 布尔值允许正式任务时，才可按总控授权进入正式链路；否则不得正式接单或发布。

## 何时使用

- 从零创建品牌或整体重定位；
- 产品已有，但客户不知道它属于什么品类或为何选择；
- 目标用户宽泛，使用、决策和付费角色混淆；
- 品牌主张通用、多个心智并列，或视觉传播缺少战略依据；
- 需要品牌架构、名称或口号候选及风险预查。

不用于日常小红书、短视频、私域获客运营，不替代商标法律检索，也不修改根注册、公共技能或其他组织资产。

## 内部模块

本 Skill 恰好有四个内部模块，按需选择模块，而不是每次全开：

1. 品类定位 `category-positioning`
2. 用户定位 `audience-positioning`
3. 差异化定位 `differentiation-positioning`
4. 心智占位 `mindshare-occupation`

品类定位先于差异化定位，差异化定位先于心智占位。用户定位必须区分使用者、决策者和付款者（付费者），并明确非首要用户；模块触发、输入、输出和禁止事项见 `references/capability-map.md`。

品牌架构、名称、口号、新品延伸等 `supportingSteps` 不是新模块，必须按 `planning-contract.md` 的固定映射、输入、证据、完成标准与停止条件调用现有四模块。

## 输入

- 总控下发的 `taskIdentity`、目标、用途与交付范围；
- 企业、品牌、产品、客户、场景、阻力和实际替代；
- 产品、技术、服务、体验、客户结果和口碑证据；
- 历史品牌、视觉、传播、竞争与命名资料；
- 总控固定的上游 `artifactId@version` 与 `sha256`。

已经由项目舱或上游固定成果提供的资料自动读取，不要求需求者重复输入。缺少不可替代事实时只能形成待验证候选。

## 执行

固定链路：

```text
前置知识检索
→ 任务规划
→ 上游版本绑定
→ 证据分类
→ 执行所选定位模块
→ 规则审核
→ 定位专业审核
→ 定向返工或双层打包
→ 返回总控
```

1. 实时读取根权威登记，再按 `planning-contract.md` 识别局部任务、全部命中的 `supportingSteps`、从零品牌或整体重定位；支撑步骤与普通定位信号的模块取规范顺序并集，不因文本先后改变结果。只选择必要模块，未选模块标记“本次未调用”。
2. 绑定当前项目舱和上游 `artifactId@version`、`sha256`，禁止引用 `current` 或不明确的“最新版”。
3. 资料顺序固定为飞书知识库 → 对话补充 → 互联网公开检索。飞书为 `no_hit` 或 `degraded` 时继续推进并告知覆盖限制。
4. 把材料按事实、推断、假设和未知分类，并建立来源冲突表；不相关的知识命中不得迁移成项目事实。
5. 按 `capability-map.md` 执行所选模块。差异化必须对用户有价值、企业可长期交付且有证据；最终只保留一个主要心智，其余降为辅助或非目标认知。
6. 需要时补充品牌架构、命名与口号预查；公开名称搜索不能替代商标法律检索，也不等于可注册或不可注册结论。
7. 规则审核检查字段、版本、证据、边界与硬失败；定位专业审核独立检查品类、用户、差异、证据、单一心智和下游可用性。
8. 审核失败时按 `debugging-playbook.md` 只返工受影响模块；两层均通过后按交付契约生成 `humanSummary` 与 `systemPackage`。
9. 候选返回总控。组织工作区不得写 `shared-artifacts/`，当前不得写 `outputs/`，不得对外发布或自行晋级正式资产。

## 输出与验收

输出至少包括：实际选择模块、证据地图、品类与用户、差异化、一个主要心智、适用的品牌架构与命名风险、视觉/传播战略简报、双审核记录和双层交付包。

验收按 `quality-rubric.md` 执行：

- 品类可理解，用户具体且角色不混淆；
- 差异化不是通用形容词，能被企业长期兑现；
- 每个关键主张能追溯到证据或标为待验证；
- 只有一个主要心智；
- 结论能指导品牌视觉和品牌传播；
- `ruleReview` 与 `professionalReview` 均通过。

## 异常、重试与停止

- 飞书 `no_hit` / `degraded`：保存真实凭证、告知限制、继续对话与公开检索，降低结论强度。
- 来源冲突：并列保留，不静默选取有利来源。
- 临时网络或文件占用最多重试两次。
- 同一根因最多三轮真实修复；三轮仍失败即停止，返回可恢复阻塞报告。
- 缺少会改变品类、首要用户或核心能力的不可替代事实：保留待验证候选；无法安全推进时返回总控请求最少业务决策。
- 付费、正式对外发布、账号权限、不可逆覆盖或商标法律结论：停止并等待授权。

## 常见错误

| 错误 | 正确处理 |
| --- | --- |
| 用“高端、专业、创新”当差异 | 回到具体能力、机制、体验与结果证据 |
| 用“年轻人、中高端”当用户 | 写角色、场景、触发、阻力、使用/决策/付费关系 |
| 同时抢多个主心智 | 选一个主要心智，其余明确降级 |
| 用公开搜索代替商标结论 | 只记录冲突预查，交由专业法律检索 |
| 为完整而运行全部模块 | 只运行任务需要且依赖成立的模块 |

## 示例

输入：“给二三线小微餐饮店做 AI 经营助手，想同时叫餐饮 AI、经营顾问、数字员工、增长神器。”

处理：区分老板、店长、收银员和代运营的角色，核对菜单毛利、每日摘要和活动建议的真实能力；拒绝无证据的节省比例，只选择一个主要心智，其余降为辅助或非目标；名称只做冲突预查；输出待验证候选和供视觉、传播读取的固定版本简报，返回总控。
