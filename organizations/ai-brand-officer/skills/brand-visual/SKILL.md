# 品牌视觉

## 帝王版成果输出

专业交付统一规则：只输出总控已经锁定的组织、技能和业务子项，不得因为“全部、全面、所有资料”等深度词自行扩大任务范围。一级标题按总控目录编号并去掉“技能”后缀，二级和三级标题沿用总控下发的编号与名称；每个二级业务子项的三级标题固定为“核心结论、数据与分析、经营建议”。四级标题仅在有助于阅读时使用，并按当前行业、地域、客群或经营问题动态命名，禁止把“关键变量、推导逻辑、已知事实、待验证信息、执行动作、验收指标、风险与停止条件”设为固定可见栏目。正文不设置固定凑字数指标，以事实密度、判断质量和行动价值验收；不得靠重复套话凑篇幅。核心结论直接回答当前对象的状态及经营含义；数据与分析必须真正给出数据、样本、对比、推导和经营影响，不得解释什么叫分析；经营建议必须写清取舍、动作、验收方式和停止条件。公开研究子项逐节至少提供2项有口径的量化事实和2个可追溯来源；任务给出地域时必须下沉到当地。禁止用“本节采用某分析链”等方法论自述、跨章节复制、模拟数字、通用模板或篇幅冒充专业深度。

强制执行 `shared/ORGANIZATION_AI_WORK_OWNERSHIP_STANDARD.md`。AI可自主完成的调研、检索、比较、测算、预算拆分、方案设计、指标反推和风险情景分析必须在本轮直接完成。经营建议是AI已经完成分析后的可执行方案，不是交给帝王的研究作业清单。只有企业内部未公开事实、现场物理条件、个人偏好与授权、正式报价或合同条件，才可作为帝王最少补充项。公开精确值暂不可得时，必须输出有依据的区间、假设、公式、敏感性分析和验证阈值，不得把AI职责改写成待办。
任务涉及设备、器械、车辆、工程设施或其他固定资产时，强制执行 `shared/CAPITAL_ASSET_PROCUREMENT_STANDARD.md`，逐项比较全新、二手和混合采购，按全生命周期成本给出金额、理由、风险和推荐结果。

唯一目录事实源为 `control-center/registries/organization-output-standard.json`。本技能在帝王版组织 Word 中固定使用一级章节“品牌视觉”，并严格按以下顺序输出：

1. 品牌视觉体系
2. 门店形象
3. 海报设计
4. 产品包装
5. AI视觉生成

每个栏目必须承接当前品牌定位、真实素材、用途和授权；概念方向不得冒充施工图、印刷成品或正式发布资产。仍缺少品牌、产品、现场或授权资料时写明：`信息不足，暂时无法形成可靠分析。当前缺少：<具体信息>。` 视觉DNA、方向比较、真实性和一致性审核融入对应栏目，不新增帝王版目录。

## 概述

把已确认品牌定位转化为可识别、可延展、可生产并可长期管理的视觉系统；漂亮不是充分条件，定位、真实性、精确文字、授权和生产边界必须同时成立。

本 Skill 是总控调用的 AI品牌官分支能力，不是总控主线。每次执行实时读取 `control-center/registries/organizations.json` 中 AI品牌官的组织状态、正式任务许可与核心 Skill 状态，不把某次成熟度快照写死在文档。根权威若显示组织侧 `pilot`，就只按试运行边界执行；只有根权威显示允许正式执行（例如进入 `operational`）且总控任务同时授权时才进入相应执行等级，否则只保留组织归属和候选，不正式接单、发布或晋级。

## 何时使用

- 建立或升级 Logo、字标、VI 和长期视觉体系；
- 规划门店门头、导视、展示、材质与灯光概念；
- 为普通海报建立品牌策略简报、视觉 DNA 和最终品牌总审；
- 建立包装视觉、标签层级、SKU 延展和印刷边界；
- 使用 AI 探索视觉主体、人物、产品场景或图像语言。

不用于日常平台运营，不在组织内复制公共海报或淘宝套图生产链路，不替代施工、法规、印刷、商标法律或对外发布审批。

## 内部模块

本 Skill 恰好包含五个按需调用的内部模块：

1. 品牌视觉体系 `visual-identity-system`
2. 门店形象 `store-identity`
3. 海报设计 `poster-art-direction`
4. 产品包装 `product-packaging`
5. AI视觉生成 `ai-visual-generation`

详细触发、输入、自动读取、输出和禁止事项见 `references/capability-map.md`。未选择模块标记“本次未调用”，不得为了完整机械生产 Logo、门店、包装、海报和 AI 图全套。

## 输入

- 总控下发的 `taskIdentity`、目标、用途、渠道与交付范围；
- 长期资产必须读取已确认品牌定位的精确 `artifactId@version` 与 `sha256`；单张轻量任务也必须执行最小定位检查；
- 品牌名称状态、现有 Logo/字体/图片/门店/包装和历史资产；
- 产品原图、产品身份指纹、人物与素材授权、支持视角；
- 参考视觉、禁用方向、帝王同项目审美档案；
- 尺寸、材质、结构、法规、印刷和现场资料（适用时）。

已在项目舱和固定上游成果中的资料自动读取，不要求帝王重复输入。不可替代事实缺失时只形成概念或待验证候选。

## 执行

固定链路：

```text
前置知识检索
→ 任务与上游版本绑定
→ 按需选择视觉模块
→ 素材/授权/原貌/通道检查
→ 参考视觉 DNA 与三方向预选
→ 专业执行或公共能力调用
→ 规则审核
→ 视觉专业审核与品牌总审
→ 定向返工或双层打包
→ 返回总控
```

1. 实时读取根权威登记，按 `planning-contract.md` 选择必要模块并保留未调用模块。
2. 上游只读精确 `artifactId@version` 与 `sha256`，禁止引用 `current`、`latest` 或模糊“最新版”。选择视觉体系、门店形象或产品包装任一长期模块时，必须存在来自品牌官且 `artifactId` 为 `brand-positioning-*` 语义的精确品牌定位上游；缺失时规划器拒绝，不进入定稿。
3. 资料顺序为飞书知识库 → 对话补充 → 互联网公开检索；`no_hit` / `degraded` 时告知限制并继续安全工作。
4. 首次建体系或审美不确定时形成三个真正不同的方向；有参考图时先提炼参考视觉DNA，包括构图、光线、色彩、字体、材质、留白和信息密度。
5. 视觉体系覆盖 Logo/字标、色彩、字体、图形、图像、版式和使用规则；AI 概念 Logo 不能冒充正式矢量资产。
6. 门店覆盖门头、导视、展示、材质和灯光；概念图不冒充施工图、结构图、消防图、电气图、造价或建成现场。
7. 包装覆盖结构适配、标签、法规字段和印刷边界；没有企业或专业依据时不得补造。
8. AI视觉生成先核人物、产品、素材授权和生图通道；产品图绑定原图 SHA-256、身份指纹与支持视角。复杂中文、Logo、型号、价格、日期、参数、二维码和法规字段采用确定性排版，不让模型承担精确文字。
9. 每次公共能力交接都重新读取根级 `public-skills/registry.json`，按 `publicSkillId` 或 `capabilityId` 解析本次 `maturity` 与 `allowedOrganizations`，不得把某次读取结果硬编码进组织文档。记录登记表路径、文件 SHA-256、读取时点；若登记表将来提供版本字段，同时记录该版本，否则以 `sha256:<digest>` 作为 `versionOrHash`。
10. 普通海报绑定 `publicSkillId = public.promotional-poster` / `capabilityId = promotional-poster`，淘宝套图绑定 `publicSkillId = public.taobao-ecommerce-image-set` / `capabilityId = taobao-ecommerce`。只有 `maturity === operational`、`allowedOrganizations` 包含 `ai-brand-officer` 且总控本次任务已授权时，才可进入正式公共能力执行；若 `maturity !== operational`，不得宣称或执行正式任务。获准后才分别引用根级 `skills/creating-promotional-posters/SKILL.md` 或 `workflows/TAOBAO_ECOMMERCE_IMAGE_SET_PILOT.md`。公共能力始终不计入品牌官三个核心技能；公共候选返回后仍由品牌官执行品牌一致性总审和最终否决。
11. 按 `quality-rubric.md` 做规则审核与独立视觉专业审核。海报另执行十项硬否决、六维 100 分与七项对比；硬否决成立或低于 80 分不得提交帝王候选。
12. 每个品牌视觉候选在 Task4 前由 `brand_visual_semantic_validator.mjs` 复验候选 Schema、三方向资产与三对差异、审美档案隔离、长期视觉定位前置和公共能力三重授权；`brandId` 与 `visualPolicyContext` 只来自可信运行时，并形成任务内不可变恢复绑定。
13. 失败按 `debugging-playbook.md` 映射根因。同一视觉根因最多三轮真实定向修复，依次为局部修正、模块重做、方法或已授权路径切换。
14. 双审核通过后生成 `humanSummary` 与 `systemPackage`，只返回总控。正式包只使用顶层 `sha256`，未知 `packageHash` 拒绝。组织工作区不得写 `shared-artifacts/`、不得写根级 `outputs/`、不得自行发布或切换正式版本。

## 输出与验收

输出至少包含：实际模块、精确上游版本、证据与授权、视觉 DNA、三方向（适用时）、模块成果、生产边界、审美档案引用、淘汰与返工、双审核以及双层交付。

必须同时满足：

- 定位承接、区别度、识别与延展成立；
- 产品原貌与精确文字正确；
- 字体、图片、人物、产品、IP 和通道授权可追溯；
- 单图、系列和参考视觉 DNA 对照通过；
- 概念、施工、法规、印刷和发布边界明确；
- `ruleReview` 与 `professionalReview` 来自不同审核身份且均通过；
- 海报候选无硬否决并达到 80 分以上。

## 帝王审美校准

只把帝王对实际候选的明确通过或明确否决写入当前企业、当前项目、当前品牌的 `aesthetic-profile-template.md`。不从沉默、停留时间或单次点击推断。审美档案企业项目隔离，禁止跨项目自动复用；确需复用时由总控建立带 `artifactId@version` 与 `sha256` 的固定导入快照。

## 异常、重试与停止

- 定位或长期资产版本缺失：停止定稿，形成待验证候选或返回总控补充；
- 产品原图、身份指纹、支持视角或授权缺失：禁止产品生图；
- 施工、法规、印刷或现场依据缺失：只做概念和占位，不给专业生产结论；
- 临时网络或文件占用最多重试两次；
- 相同视觉根因三轮仍失败：停止并返回可恢复阻塞报告；
- 改变产品、真人、场景或展示方式，付费、正式发布、账号权限或不可逆覆盖：停止并请求最少必要决定。

## 常见错误

| 错误 | 正确处理 |
| --- | --- |
| “高端科技”直接变黑金棚拍 | 转译为可验证构图、光线、色彩、字体、材质与留白 |
| 一个参考图直接照着做 | 先提炼视觉 DNA 和反面模式，再做三个不同方向 |
| AI 同时生成主体和复杂文字 | 先视觉主体，后确定性排版 |
| 公共海报通过就直接交帝王 | 回到品牌官做定位、DNA、原貌、文字和整体质量总审 |
| 用户没反对就写入偏好 | 只记录明确通过或否决 |

## 示例

输入：“做成高端科技黑金，一次给 Logo、门店、包装、海报和九张电商图。”

处理：绑定定位与项目版本，把抽象词拆成视觉 DNA，按真实目标选择模块并做三个方向；缺产品、门店、包装或法规资料的部分只给概念。每个公共交接先读取根登记表并按当次成熟度与组织许可决定是否可执行，候选回收后再做品牌总审；不把公共能力计入三个核心 Skill。
