# 品牌传播质量量表

## 两层审核

先由规则审核检查身份、字段、版本、事实、禁语和组织边界，再由不同审核人执行独立传播专业审核。`ruleReview.reviewerId` 与 `professionalReview.reviewerId` 必须不同；专业审核只读任务、证据、候选和本量表，不继承执行者解释。

任一层失败均不得进入 `candidate_ready`。

## 专业审核标准

| 标准 | 通过条件 | 失败示例 |
| --- | --- | --- |
| 定位一致 | 核心信息承接固定版本的品类、用户、差异和主要心智 | 为追热点改写品牌是谁 |
| 单一核心信息 | 一个项目只有一个主张，其余均服务于该主张 | 同时争抢“便宜、专业、高端、创新” |
| 能理解、记住、相信 | 受众看得懂、能复述、知道为何可信 | 只有漂亮口号，没有意义与信任理由 |
| 承诺证据 | 每个能力、案例、数据、荣誉和效果承诺都有安全 `claimKey` 与非空确认级 `claimDigest`；候选实际文本重算摘要、候选填写摘要和每条真实 `evidence.claim` 重算摘要三方完全一致 | 用无关荣誉、无主张键证据、同键异义、自报摘要、不同文案借摘要、多证据混入异义事实或跨主张复用代替证据 |
| 故事真实 | 起源、冲突、选择、价值和证据可以回溯 | 虚构白手起家、客户见证或成功结果 |
| 创始人与品牌关系 | 真实身份、观点边界、可信证据和品牌责任清晰 | 人设凌驾产品与品牌，或无关观点抢占品牌 |
| 视觉一致 | `visualBindings` 与固定视觉规范不冲突 | 文案语气与视觉语言割裂 |
| 可给增长适配 | 母题、证据、语气、禁区足以让 AI增长战略官做渠道适配 | 直接替增长官写30天日更和投流计划 |
| 成交边界 | 事实锁可供成交官使用，但不代写销售策略 | 把成交话术或脚本错误交给增长官 |
| 结果承诺边界 | 明确不保证增长或成交，未知和适用条件清楚 | 宣称“使用后必增长、必成交” |

## 硬失败

以下任一项出现即失败，不能由语言好看抵消：

- 定位版本未固定或 SHA-256 不匹配；内容传播/品牌活动未固定视觉，或纯故事/创始人任务伪造视觉引用；
- `proofLibrary`、故事、创始人IP或活动的证据 ID 不存在于本次证据包，或确认级表达只绑定判断、推断、假设、未知及低置信证据；
- 核心信息、支持信息、信任理由或内容母题缺少 `claimKey` / `claimDigest`，证据 `claimKey` 不一致，同一证据跨不同主张复用；
- 确认级 `claimDigest` 为空，或候选实际主张文本、候选填写摘要与任一真实 `evidence.claim` 的归一化重算摘要不完全一致；候选自报摘要、不同文案借用证据摘要及多证据异义均不得通过；
- 明确目标模块被 `requestedModuleIds` 少报，或伪造上游成果 ID 绕过定位/视觉门禁；
- `communication-policy-context.json` 缺失、篡改或漂移后复用旧候选或旧审核；
- 多个相互竞争的核心信息；
- 无证据宣称、虚构故事、虚构创始经历或案例；
- 创始人IP脱离品牌真实能力；
- 进入小红书种草、短视频日更、公众号日常、私域运营、投流获客、渠道排期与预算；
- 进入销售沟通、成交话术、成交脚本或成交策略；
- 保证增长、保证成交或自动对外发布；
- 两层审核为同一个 `reviewerId`。

## 审核输出

审核必须返回：候选与任务绑定、评分、硬失败、失败标准、根因、受影响模块、修正目标、审核人身份和时间。只有规则审核与专业审核都通过，才能进入双层打包。
