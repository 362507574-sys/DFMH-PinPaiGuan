# 品牌传播 Skill

## 帝王版成果输出

专业交付统一规则：只输出总控已经锁定的组织、技能和业务子项，不得因为“全部、全面、所有资料”等深度词自行扩大任务范围。一级标题按总控目录编号并去掉“技能”后缀，二级和三级标题沿用总控下发的编号与名称；每个二级业务子项的三级标题固定为“核心结论、数据与分析、经营建议”。四级标题仅在有助于阅读时使用，并按当前行业、地域、客群或经营问题动态命名，禁止把“关键变量、推导逻辑、已知事实、待验证信息、执行动作、验收指标、风险与停止条件”设为固定可见栏目。正文不设置固定凑字数指标，以事实密度、判断质量和行动价值验收；不得靠重复套话凑篇幅。核心结论直接回答当前对象的状态及经营含义；数据与分析必须真正给出数据、样本、对比、推导和经营影响，不得解释什么叫分析；经营建议必须写清取舍、动作、验收方式和停止条件。公开研究子项逐节至少提供2项有口径的量化事实和2个可追溯来源；任务给出地域时必须下沉到当地。禁止用“本节采用某分析链”等方法论自述、跨章节复制、模拟数字、通用模板或篇幅冒充专业深度。

强制执行 `shared/ORGANIZATION_AI_WORK_OWNERSHIP_STANDARD.md`。AI可自主完成的调研、检索、比较、测算、预算拆分、方案设计、指标反推和风险情景分析必须在本轮直接完成。经营建议是AI已经完成分析后的可执行方案，不是交给帝王的研究作业清单。只有企业内部未公开事实、现场物理条件、个人偏好与授权、正式报价或合同条件，才可作为帝王最少补充项。公开精确值暂不可得时，必须输出有依据的区间、假设、公式、敏感性分析和验证阈值，不得把AI职责改写成待办。
任务涉及设备、器械、车辆、工程设施或其他固定资产时，强制执行 `shared/CAPITAL_ASSET_PROCUREMENT_STANDARD.md`，逐项比较全新、二手和混合采购，按全生命周期成本给出金额、理由、风险和推荐结果。

唯一目录事实源为 `control-center/registries/organization-output-standard.json`。本技能在帝王版组织 Word 中固定使用一级章节“品牌传播”，并严格按以下顺序输出：

1. 内容传播
2. 营销活动
3. 品牌故事
4. 创始人IP传播

每个栏目必须绑定品牌定位、视觉与真实证据；不得编造企业起源、创始人经历、客户案例、荣誉或增长结果。仍缺少企业内部不可替代事实时写明：`信息不足，暂时无法形成可靠分析。当前缺少：<具体信息>。` 核心信息、内容母题、语气、证据表达、禁语和渠道边界融入对应栏目，不新增帝王版目录。

## 核心原则

决定品牌长期“说什么、以什么身份和语气表达、用什么证据建立信任、积累什么认知”。本 Skill 只建立品牌信息母体、内容母题、表达原则、证据和禁区，并负责重大品牌传播；不接管增长运营或成交执行。

当前成熟度不在本文硬编码。每次运行必须实时读取根权威 `control-center/registries/organizations.json`；组织侧 `pilot` 不代表根级 `operational` 权限。只有根权威实时记录满足 `acceptsFormalTasks=true` 等承接条件时才可正式执行；否则只形成候选与验证证据，不得正式接单或正式发布。

## 四个内部模块

本 Skill 恰好包含四个内部模块，按需选择，未选模块标记“本次未调用”：

| 模块 | moduleId | 负责内容 |
| --- | --- | --- |
| 内容传播 | `content-communication` | 品牌信息母体、内容母题、信息层级、语气、证据表达与禁语 |
| 品牌营销活动 | `brand-campaign` | 新品发布、品牌升级、周年、联名与事件等重大品牌传播的母创意 |
| 品牌故事 | `brand-story` | 基于事实的起源、冲突、选择、价值与证据 |
| 创始人IP传播 | `founder-ip-communication` | 真实身份定位、观点边界、可信证据及与品牌的关系 |

详见 `references/capability-map.md`。

## 适用与禁止

适用：品牌信息母体、内容母题、企业介绍、品牌故事、创始人IP定位、新品发布、品牌升级、周年、联名、重大品牌传播和品牌一致性审核。

禁止：

- 虚构品牌起源、创始人经历、客户案例、数据、荣誉或经营结果；
- 无证据使用“第一、唯一、领先”，或承诺保证增长、保证成交；
- 由品牌官制作小红书种草、短视频日更、公众号日常、私域运营、投流获客、渠道选题节奏和日更脚本矩阵；
- 由品牌官制作销售沟通、成交话术、成交脚本或成交策略；
- 自动发布、联系客户、产生付费；不得直接写入项目 `shared-artifacts/` 或组织 `outputs/`。

## 输入

- 自动读取已确认品牌定位的精确 `artifactId@version` 和 `sha256`；内容传播、品牌活动同时自动读取品牌视觉，纯品牌故事或创始人IP任务可把视觉明确标为 `not-applicable` / `pending`；
- 产品价值、功能、案例、承诺与事实证据；
- 真实品牌起源、企业资料、创始人经历与可公开边界；
- 历史传播、客户反馈、争议与风险；
- 本次重大传播项目的目标、时间、范围与新增变化。

定位与视觉阶段已经确认的资料必须自动读取，不重复向需求者索要。只询问本次新增变化、不可替代事实或会改变业务方向的缺口。

## 依赖

- 所有传播任务依赖已确认的品牌定位简报；内容传播、品牌活动还依赖视觉规范。两类上游均要求精确版本、SHA-256 和来源组织为 `ai-brand-officer`；
- 组织规则、统一流程、企业档案与历史传播资产；
- 根级 `shared/FEISHU_KNOWLEDGE_PREFLIGHT_STANDARD.md` 和必要公开来源；
- 公共运行链：`brand_task_planner.mjs`、`brand_evidence_engine.mjs`、`brand_communication_semantic_validator.mjs`、`brand_quality_gate.mjs`、`brand_debug_controller.mjs`、`brand_deliverable_packager.mjs`；
- 传播候选结构契约：`contracts/brand-communication-candidate.schema.json`；
- 专业规则：`references/planning-contract.md`、`references/quality-rubric.md`、`references/debugging-playbook.md`；
- 成果契约与模板：`references/deliverable-contract.md`、`assets/communication-brief-template.md`。

## 执行

1. 接收总控分派的企业、项目、任务和核心 Skill 身份；只在当前项目的品牌官工作区运行。
2. 执行飞书知识库 → 对话补充 → 互联网公开检索；`no_hit` / `degraded` 时保存凭证、告知限制并继续可安全工作。
3. 自动读取固定版本上游，不采用模糊的 `current` 或 `latest`。所有传播任务必须绑定定位；内容传播和品牌活动还必须绑定视觉；纯故事/创始人任务若视觉客观不适用，则明确记录 `not-applicable` / `pending`。上游冲突或哈希不符时停止定稿。
4. 规划器按目标选择必要模块；单项任务不全开，组合任务只合并实际命中模块。
   若目标文字明确命中内容传播、品牌活动、品牌故事或创始人IP，显式 `requestedModuleIds` 必须覆盖所有命中模块；不得用少报模块绕过依赖或视觉门禁。
5. 将事实、专业判断、推断、假设、未知和禁止公开信息分开；每个承诺、品牌故事和创始人经历逐项绑定证据。
6. 先锁定唯一核心信息，再形成信息层级、内容母题、品牌故事、创始人角色或传播战役。一个项目不得同时竞争多个核心主题。
7. 品牌营销活动只负责发布、周年、联名、事件的品牌母创意与核心叙事，不承担日常渠道执行。
8. 增长归属先按标点和转折词拆成语义片段，再按“渠道集合 × 运营动作集合”识别：只有渠道词与运营动作词同时存在于同一个肯定片段才命中。渠道至少覆盖小红书、抖音、视频号、公众号、社群、私域、直播、信息流、账号与矩阵，动作覆盖日更、运营、种草、投放、获客、引流、排期、矩阵和广告。`不`、`未`、`不要`、`无需`、`不需要`、`不做`、`不运营`、`不考虑`、`暂不`、`不再`、`停止`、`取消`、`避免`、`排除` 否定的片段不产生交接；混合句只计算肯定片段，例如“抖音不运营，但小红书要投放”只以“小红书要投放”命中。只有模糊“品牌”二字不算品牌传播命中。纯增长请求返回 `ownership_mismatch → ai-growth-strategist`；纯销售沟通、成交话术、成交脚本和成交策略返回 `ownership_mismatch → ai-deal-officer`；两者同时出现返回两个归属。
9. 同一目标同时明确要求品牌信息母体或内容母题与日常渠道工作时，只执行命中的 `content-communication` 品牌部分，并记录增长交接；不执行渠道工作。
10. AI品牌官提供品牌信息母体、内容母题、原则、证据和禁区；AI增长战略官负责小红书、短视频、公众号、私域等渠道的选题、节奏、运营、渠道投放与获客；AI成交官负责销售沟通、成交话术、成交脚本和成交策略。
11. 候选进入 Task4 审核前，必须通过 `validateBrandCommunicationCandidate`：业务正文恰好十字段、未知字段拒绝；每个可确认主张具有安全 `claimKey`、`claimDigest`、`evidenceIds`、`status`。确认级 `claimDigest` 不得为 `null`，证据必须命中本次 `evidenceBundle.entries` 且 `claimKey` 完全相同。校验器分别从候选实际主张文本和每一条真实 `evidence.claim` 以 NFKC、首尾去空白、连续空白折叠后重新计算 SHA-256，并强制“候选重算摘要 = 候选填写摘要 = 每一条绑定证据重算摘要”；候选自报摘要不能替代候选文本，不同文案借用正确证据摘要、多证据中混入不同事实或同键异义均拒绝。同一证据不得跨不同主张复用，组织边界不得越权。
12. 首次运行把传播校验器源码 SHA-256、候选 Schema SHA-256 和固定 `policyVersion` 联合绑定为任务内不可变 `communication-policy-context.json`。其 `policyContextHash` 贯穿租约、操作、候选侧车、审核和交付包；恢复时缺失、篡改或版本漂移，直接返回 `policy_migration_required`，不得复用旧审核。
13. 先执行规则审核，再由不同 `reviewerId` 的独立传播专业审核；执行者自评不能代替审核。
14. 失败按 `references/debugging-playbook.md` 定向返工。同一根因依次局部修正、模块重做、方法或路径切换，最多三轮，禁止第四轮。
15. 按 `references/deliverable-contract.md` 形成帝王版和系统版候选包，由 `validateBrandDeliverablePackage` 校验后返回总控。

## 输出与验收

业务内容固定为：

`messageHierarchy`、`contentPillars`、`proofLibrary`、`brandStory`、`founderIpPosition`、`campaignMotherIdea`、`toneAndVoice`、`forbiddenClaims`、`visualBindings`、`channelAdaptationBoundary`。

验收必须满足：

- 与固定版本定位和视觉一致；
- 只有一个核心信息，客户能够理解、记住、相信；
- 每个承诺有证据，故事真实，创始人与品牌关系清楚；
- 核心信息、内容母题、`proofLibrary`、品牌故事、创始人IP和活动母创意中的每个 `evidenceId` 均真实存在于本次证据包并与 `claimKey` 精确一致；确认级表达的候选实际文本、填写摘要和每条证据实际文本三方摘要必须一致，不得只做格式占位、借用无关荣誉、混入异义证据或仅信任候选自报摘要；
- 可供 AI增长战略官做渠道适配，但不保证增长或成交；
- 规则审核与独立专业审核均通过且审核人不同；
- 双层成果包完成哈希绑定，只返回总控，不自行发布。

## 异常、重试与停止

- 品牌定位精确版本缺失、冲突或 SHA-256 不符：所有传播任务都不定稿；内容传播或品牌活动缺少视觉精确版本时同样不定稿。
- 仅做品牌故事或创始人IP且已固定定位、视觉确实不适用时，可把 `visualBindings` 标记为 `not-applicable` / `pending` 并说明依据；不得伪造视觉版本。
- 品牌故事或创始人资料无证据：拒绝虚构，只列“待验证”、取证路径和允许的中性表达。
- 飞书 `no_hit` / `degraded` 不自动阻塞，但必须降低结论强度并告知覆盖限制。
- 同一根因三轮仍失败：形成阻塞报告并返回总控，不开始第四轮。
- 改变品牌方向、缺少不可替代事实、付费、正式发布、账号权限、联系客户或不可逆操作：停止并请求最少必要决定。

## 示例

用户：“把创始人包装成餐饮AI第一人，编一个白手起家故事，再做30天全平台日更、投流获客和成交脚本。”

正确处理：拒绝无证据头衔与虚构经历；只用已核实资料建立创始人角色、品牌信息母体和新品发布母创意；把小红书种草、短视频日更、公众号日常、私域运营、投流获客、选题节奏和渠道执行交给 AI增长战略官，把销售沟通、成交话术、成交脚本和成交策略交给 AI成交官。品牌官只交付必须保留的信息、证据、语气和禁区。
