# 品AI品牌官｜长期决策

## D-001｜组织架构与技能边界

- 日期：2026-07-28
- 决策：遵循“一个控制中心、五个业务组织、十五个核心技能”。AI品牌官只是由总控调用的业务组织分支，不是总控主线、控制中心或总体调度器；该分支固定拥有品牌定位、品牌视觉、品牌传播三个核心 Skill。
- 边界：普通宣传海报 = `formal` 公共能力；淘宝电商套图 = `pilot` 公共能力，均不计入三个核心技能。

## D-002｜历史连接状态（已被 D-011 替代）

- 日期：2026-07-28
- 决策：`rootControllerRegistration = not_connected`；`peerOrganizationCalls = contract_only`。
- 影响：不得宣称根控制中心或同级协作已经完成生产连接；协作只能先形成契约候选。
- 当前效力：其中 `not_connected` 的本地登记值已由 D-011 替代；当前本地值为 `registered_designing`。本条仅保留历史，不得作为当前状态。

## D-003｜主责、企业与资产隔离

- 日期：2026-07-28
- 决策：控制中心确定唯一主责；锁定任务归属后主责不转移。
- 决策：企业隔离和候选与正式隔离都是强制门禁。当前品牌官总审和帝王验收只形成候选反馈与试运行证据，不能把候选转成正式品牌资产。
- 根门槛：只有根控制中心未来将本组织升级为 `operational` 且 `acceptsFormalTasks = true`，才具备进入当时有效正式晋级流程的必要前提。

## D-004｜知识资料顺序

- 决策：资料顺序固定为“飞书知识库 → 对话补充 → 互联网公开检索”。
- 降级：飞书 `no_hit` 或 `degraded` 时告知限制并继续，不得卡住任务或虚构依据。知识写回保持 `disabled`。

## D-008｜根权威成熟度高于组织候选配置

- 日期：2026-07-28
- 权威状态：`control-center/registries/organizations.json` 当前记录 AI品牌官 `status = designing`、`acceptsFormalTasks = false`，三个核心技能均为 `designing`。
- 决策：组织配置中的三个核心 Skill `pilot` 只表示组织侧候选验证成熟度，不等于根权威成熟度。
- 影响：根状态升级为 `operational` 且 `acceptsFormalTasks = true` 前，只能形成候选与验证证据，不得正式接单、正式晋级或写入 `outputs/` 正式成果；帝王验收不能绕过此门槛。

## D-009｜三个核心 Skill 的组织侧首轮基线

- 日期：2026-07-28
- 决策：品牌定位、品牌视觉与品牌传播分别建立完整 Skill、交付契约、候选模板和调用说明，组织配置统一升级为 `pilot`。
- 自动继承：品牌视觉读取已确认的品牌定位；品牌传播读取已确认的品牌定位与视觉规范，不再要求帝王重复输入已有资料。
- 职责边界：品牌传播负责品牌信息、内容母题、真实品牌故事、创始人 IP、重大品牌传播战役和一致性审核；日常渠道运营、投放获客、客户培育与复购归 AI增长战略官，成交话术归 AI成交官。
- 限制：此次只升级组织侧候选验证成熟度；不修改根注册表，不宣称正式接单、根连接或同级组织连接完成。

## D-010｜AI品牌官是总控调用的组织分支

- 日期：2026-07-28
- 决策：总控负责理解任务、选择组织和总体编排；AI品牌官只在总控分派品牌任务时作为业务组织分支被调用。
- 边界：AI品牌官内部只拥有品牌定位、品牌视觉、品牌传播三个核心 Skill，不承担总控主线、根路由、全局调度或其他组织管理职责。
- 任务主责含义：品牌官被分派后只对该品牌任务的结论与总审负责，不等于成为系统主线。

## D-011｜组织本地登记与根设计态运行映射对齐

- 日期：2026-07-29
- 事实：根 `control-center/registries/organization-runtime.json` 已为 AI品牌官绑定组织配置路径，并登记品牌定位、品牌视觉、品牌传播三个可加载 Skill；继续使用 `not_connected` 会触发总控健康警告。
- 决策：D-002 中的组织本地登记值由 `not_connected` 更新为 `rootControllerRegistration = registered_designing`。
- 含义：只表示本组织已进入根设计态运行映射，不代表生产连接、正式开放或同级组织直连。根权威继续为 `designing`、`acceptsFormalTasks = false`，三个技能继续为组织侧 `pilot`。
- 质量标准：三个技能各自绑定独立 Workflow，统一质量档案为 `quality/organization-quality.json`；当前证据等级为模拟验证，下一门槛是真实企业内部任务和跨组织回传闭环。
- 权限：本决策不修改根注册表、根运行映射、根测试或根保护基线。

## D-012｜三个核心 Skill v2 共用五个运行组件

- 日期：2026-07-30
- 决策：品牌定位、品牌视觉、品牌传播共用任务规划器、证据引擎、质量门禁、调试控制器、成果打包器五个确定性运行组件。
- 边界：运行组件只负责模块选择、证据与版本约束、状态推进、双审核、三轮停止、恢复和双层交接，不替代三个 Skill 生成业务内容，也不形成第四个 Skill。

## D-013｜十三个内部模块不增加 Skill 数量

- 日期：2026-07-30
- 决策：定位四模块、视觉五模块、传播四模块都属于相应 Skill 内部能力；系统按目标只选择必要模块。
- 边界：组织核心 Skill 始终且仅有 `brand-positioning`、`brand-visual`、`brand-communication` 三个，任何未知 Skill 或模块 ID 均拒绝。

## D-014｜普通海报生产权与品牌质量否决权分离

- 日期：2026-07-30
- 决策：普通宣传海报由根级公共 Skill 负责具体生产，AI品牌官负责品牌策略简报、参考视觉 DNA、品牌一致性总审和最终质量否决。
- 授权：每次调用动态核对公共登记成熟度、允许组织、当前项目 `publicSkillIds` 和总控任务绑定；候选自报授权无效。
- 边界：公共海报能力不计入三个核心 Skill，品牌官不得复制公共生产实现或自行发布。

## D-015｜海报硬否决、100 分制与三轮停止

- 日期：2026-07-30
- 决策：任何硬否决直接淘汰且不能被高分抵消；无硬否决后按 100 分制和七项视觉对比判定，`90–100` 为优选、`80–89` 为候选、`70–79` 为返工、低于 `70` 淘汰。
- 停止：同一根因最多定向返工三轮；第三轮仍未通过转 `blocked`，带证据返回总控，不打包低质量结果。

## D-016｜帝王审美档案按企业和项目隔离

- 日期：2026-07-30
- 决策：只记录帝王对实际候选的明确通过或否决，不从沉默、停留时间或单次点击推断审美偏好；审美档案与企业、项目、品牌绑定。
- 复用：跨项目复用必须由总控建立带来源项目、精确版本和 SHA-256 的固定导入快照。首次项目真实无档案时使用 `null`，不能用空对象伪装，也不豁免三个方向门禁。

## D-017｜品牌传播与增长、成交的职责边界

- 日期：2026-07-30
- 决策：品牌传播负责长期品牌信息、内容母题、重大品牌传播战役、真实品牌故事和创始人 IP 母体；小红书、抖音、公众号、私域日更、投流、获客、培育和复购归 AI增长战略官，销售话术、成交脚本和成交策略归 AI成交官。
- 执行：遇到纯增长、纯成交或混合目标时，传播 Skill 分别拒绝越界或拆出协作交接，不静默吞并其他组织工作。

## D-018｜双层候选交接与精确版本依赖

- 日期：2026-07-30
- 决策：每个通过双审核的候选同时生成面向帝王的 `humanSummary` 与面向总控/授权下游的 `systemPackage`，最终承诺使用唯一顶层 SHA-256。
- 依赖：下游只读取总控任务上下文中精确的 `artifactId@version + SHA-256`，并校验企业、项目和来源组织；不得引用模糊的“最新版本”或扫描其他组织。
- 发布：组织打包器只写当前任务候选目录，不能直接写 `shared-artifacts/`；发布、版本切换和跨组织绑定仍归总控。

## D-019｜语义门禁、证据主张与不可变策略上下文

- 日期：2026-07-30
- 决策：视觉和传播在通用质量审核前执行专用语义校验；确认性传播主张必须满足候选正文、规范化 `claimDigest` 与绑定证据真实主张三方一致。
- 恢复：传播规则、Schema、语义校验器和策略版本形成任务内不可变策略上下文；缺失或漂移转 `policy_migration_required`，保存迁移审计且不复用旧审核。
- 可靠性：执行租约、稳定操作标识、幂等键、旁证承诺和有限资源预算共同防止并发重复交付、恢复串改与无限重试。
